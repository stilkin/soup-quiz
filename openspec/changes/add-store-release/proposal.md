# Proposal

## Why

The app is feature-frozen as 1.0 and validated on Android hardware, but it exists only as
sideloaded tester APKs. Publishing to Google Play and the Apple App Store — the stores the
project has accounts for — turns the tester build into the product. Doing it now captures
the momentum of a clean, all-green codebase instead of stacking it behind new features.

## What Changes

- A `production` EAS build profile producing signed store artifacts: an Android `.aab`
  (continuing the `versionCode` lineage past the tester builds) and an iOS `.ipa`
  (bundle ID `be.pocito.soupquiz`, first distribution credentials managed by EAS).
- An iOS **simulator** build profile — unsigned, credential-free — so the first-ever iOS
  execution happens on our MacBook Pro simulator, not in App Review.
- `app.json` gains the iOS bundle identifier and store-ready version bookkeeping
  (`versionCode` 12, iOS build number 1).
- A privacy policy published at a stable public URL (GitHub Pages off this public repo):
  the app collects nothing, all data stays on-device — the page says exactly that.
- Store listing kit, committed to the repo: Play Store and App Store copy, and a Play
  feature graphic generated by the existing identity-asset script (reproducible, offline,
  same bowl-mark family). Screenshots are captured from real app runs (Android device,
  iOS simulator).
- A staged rollout, user-gated: Android ships via the Play internal track with an
  in-place-upgrade check over the tester APK before production; iOS passes a simulator
  smoke checklist before its App Store submission. Apple-side submission rides the
  App Store Connect API with a scoped key (bundle ID, metadata, screenshots, and the
  binary itself via Apple's `buildUploads`); Play uploads stay manual; the final
  Submit for Review stays a human click.
- Ride-along fix: keyboard avoidance for the country `SearchSelect` used by the daily
  challenge (backlog item; iOS punishes the current behavior more than Android). No spec
  delta — no current spec speaks to keyboard behavior; this is implementation quality.

## Capabilities

### New Capabilities

(none — this extends the existing build-and-distribute capability)

### Modified Capabilities

- `release-builds`: grows from internal/tester distribution to store distribution — new
  requirements for signed store artifacts with monotonic version codes, a published
  privacy policy, a reproducible store listing kit, and a staged rollout in which the
  first iOS execution is never App Review.

## Impact

- `apps/soup-quiz/app.json` — iOS bundle ID, versionCode 12, iOS build number.
- `apps/soup-quiz/eas.json` — `production` and iOS-simulator profiles alongside `preview`.
- `apps/soup-quiz/assets/make_app_icon.py` (+ generated outputs) — feature graphic.
- `apps/soup-quiz/src/components/SearchSelect.tsx` — keyboard avoidance.
- New: privacy policy page + listing copy under `docs/` (published via GitHub Pages).
- External: Google Play Console (internal → production tracks), App Store Connect
  (TestFlight optional, then review), EAS credentials (first iOS distribution cert).
- No package dependency changes; dataset, engine, stats, and specs of gameplay untouched.
