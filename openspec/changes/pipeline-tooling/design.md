# Design

## Context

`pnpm lint`/`format`/`typecheck`/`test` already cover the five TS packages; the
pipeline under `data/pipeline/` is plain Python (stdlib + pycountry + Pillow) in a
gitignored venv, run stage-by-stage by hand. Its tests-live-elsewhere posture (TS data
suite gates the compiled output) caught shipped-dataset problems but never the
transform regressions that produced them. The repo has no Python config file at all.

## Goals / Non-Goals

**Goals:**

- One command per check for Python, mirroring the pnpm verbs.
- Unit tests that fail the moment a transform rule regresses.
- A real coverage number for the TS packages.

**Non-Goals:**

- Enforcing coverage thresholds, adding CI, testing the Expo app.
- Type-annotating or refactoring the pipeline beyond importability and lint/format
  fixes.

## Decisions

- **D1 — Ruff as the single lint+format tool.** Its formatter is Black-compatible, so
  one tool replaces the Ruff+Black pair; `line-length = 100` matches Biome's
  `lineWidth`. Default rule set plus `I` (import sorting). Config lives in
  `data/pipeline/pyproject.toml` — pipeline-scoped, not repo-root, because the repo's
  tooling story is otherwise all Node.
- **D2 — MyPy baseline, deliberately lenient.** Defaults + `ignore_missing_imports`
  (pycountry ships no stubs; Pillow types are fine). No strict flags: the first run is
  a baseline to read, not a wall to satisfy. Findings that imply behavior changes are
  reported to the user, not silently fixed.
- **D3 — PyTest targets transforms, not the pipeline run.** The TS `data` suite
  already pins the output contract end-to-end; Python tests add value exactly where
  bugs lived: `strip_wikitext` (template nesting loop, `[[File:]]` removal, paren
  husks), `split_params` (depth-aware splitting, own-`{{` skip), `lead_photo`,
  underscore/space title normalization, and the centroid ISO property fallback chain
  (`ISO_A2_EH` → `ADM0_A2` → `SOV_A2`, `-99` handling) against a tiny inline GeoJSON
  fixture. Stage scripts become importable by moving top-level run code under
  `main()` guards — mechanical, no behavior change.
- **D4 — Coverage is report-only.** Add `@vitest/coverage-v8` alongside vitest in the
  four packages, root script `test:coverage` runs their suites with `--coverage`.
  No thresholds until we've read the number and decided it's worth enforcing.
- **D5 — pnpm as the single entry point.** Root scripts `lint:py`, `typecheck:py`,
  `test:py` exec the venv tools with `data/pipeline` as cwd. Missing venv fails loudly
  with the shell's "not found" — the README documents the setup, same as today.

## Risks / Trade-offs

- [Python dep versions unpinned (venv is regenerated by hand)] → README documents the
  three additions; `pyproject.toml` lists them as optional tooling deps with minimum
  versions.
- [First ruff/mypy pass may flood findings in old code] → formatting is applied
  mechanically via `ruff format`; lint violations are auto-fixed only where safe
  (`--fix`), the rest reviewed and either fixed trivially or recorded.
- [Importability refactor touches working scripts] → guards only move code, stages
  still run identically via `python NN_*.py`; a re-run of one stage smoke-checks it.

## Migration Plan

Additive config/tests/scripts; the only code churn is `main()` guards and ruff's
mechanical formatting. Rollback = revert the commit; the venv additions are inert.
